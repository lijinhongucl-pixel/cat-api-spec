# 贡献指南

## 欢迎你来。

但在你开始之前，有几件事需要讲清楚。

### 这份文档的文体

CAT API 用工程文体写猫——把猫写成「系统」，把你写成「Staff」。
这不是装饰，是方法。
你要提交的内容也应该保持这个文体。
如果你不确定，先读一遍 [《口吻与文体》](../reference/voice.html)。

### 什么可以贡献

- **新附录**：新增一个尚未被覆盖的场景（如航空托运、多猫家庭、导盲猫协议）
- **新的量化公式**：带公开信源等级标注（A / B / C），来源可追溯
- **新的表情状态**：13 维参数向量里你发现了一个尚未定义的稳态
- **翻译**：英文版（如果你有兴趣）
- **工具页**：新的可运行工具，但不接受纯装饰性的页面

### 什么不可以

- 不接受改变核心架构的提交（Owner 角色定义、权限模型、领地协议层级）
- 不接受把猫改成狗的提交（已有别的项目了）
- 不接受没有信源的「量化数据」
- 不接受改变文体的提交（把「系统」改回「猫」）

### 提交流程

1. Fork → 新分支 → 提 PR
2. PR 标题写清楚做了什么
3. 如果是新增量化参数，在 PR 描述里给出：
   - 公式
   - 信源（DOI / 临床指南编号 / 期刊名）
   - 来源等级（A / B / C）
4. 等审核。审核可能会很慢——不是因为不尊重你，是因为猫的时间表不接受调优。

### 文件结构约定

```
spec/          正文章节（HTML 单页，锚点跳转）
reference/     参考页（口吻 / 速查 / 错误码 / 术语表）
tools/         可运行工具（每个工具自带引擎 JS）
sdk/           SDK 控制台
assets/js/     引擎文件（浏览器 + Node 双用，零依赖）
assets/css/    共享样式（spec.css / livecat.css）
assets/img/    图片（SVG 优先）
docs/          你在这里
```

### 引擎文件约定

- 零依赖。不引 jQuery / D3 / 任何外部库。
- 浏览器 + Node 双用。用 UMD 风格 `(function(root, factory) { ... })(...)`。
- 函数式。引擎只暴露纯函数，不碰 DOM（渲染函数除外）。
- 页面上不写死数字。所有参数从引擎读。

### 不接受参数调优

这条不是开玩笑。本项目的核心立论就是「系统不接受参数调优」——
你不能提交一个 PR 把猫的日均睡眠从 13-16 小时改成 8 小时，
即使你家猫确实只睡 8 小时。
那是你家猫的事，不是本规范的事。
