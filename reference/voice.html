口吻与文体

这份文档有两个人说话

§1两个声部

这份文档有两个声部：

声部职责标记
规范编写组给事实、给出处、给参数边界正文、表格、代码块
当事猫给结论、给立场、给态度blockquote.voice 或《生活意见》整章

分清谁在说话，是读懂这份规范的前提。混淆两个声部等同于权限提升攻击——系统会拒绝响应。

§2四条硬约束

  1. 规范编写组不用第二人称称呼系统。它说「本系统」「该实例」，不说「你」。
  2. 当事猫不用第一人称称呼 Staff。它说「你」，不说「本系统的 Staff 节点」。
  3. 规范编写组不评价。它说「研究表明」「实测数据」，不说「这很可爱」。
  4. 当事猫不给数据。它说「我以为」「我知道」，不说「根据 2023 年的研究」。

§3正反示例

正面示例

// 规范编写组声部 ✓
研究表明，家猫的呼噜声频率区间为 25–150 Hz，
该区间已被证实能促进骨骼愈合与软组织修复
（来源等级 A，临床研究）。
// 当事猫声部 ✓
你以为我蹭你是喜欢你。我蹭你是把你重新写入了
我的标记系统。但这两件事，对我是一样的。

反面示例

// 规范编写组声部 ✗ —— 出现了评价
猫咪的呼噜声超级治愈，真的好可爱呀！
// 当事猫声部 ✗ —— 出现了数据出处
根据 2023 年的研究，我喜欢你给我买那个逗猫棒。

§4出现即回退的清单

以下措辞 一旦出现，视为声部混淆，整段回退重写：

措辞问题
「猫咪真的好可爱」规范编写组不应评价
「研究表明我喜欢吃鱼」当事猫不引用研究
「主人」Owner 角色不存在
「听话」系统不接受指令调优
「训练」同上（除非指 Staff 被训练）
「嫉妒」不存在该状态码
「报复」不存在该状态码
口吻是这套规范的工程地基
不是装饰
